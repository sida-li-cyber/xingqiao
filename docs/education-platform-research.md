# 星桥教育平台化调研：功能需求、UI 重设计与输入输出接口

> 编制日期：2026-08-25
> 背景：用户反馈 ①实验教学入口找不到 ②作为教学平台 UI 是否需要重设计 ③实验平台的输入/输出接口应明显。
> 结论先行：入口为代码缺陷**已修复**；UI 建议**双模式拆分**（演示大屏 + 独立教学实验台）；输入输出建议**Schema 驱动的显式接口**。以下为完整调研依据与分期实施方案。

## 一、入口问题：已定位并修复（缺陷，非设计问题）

**现象**：页面上找不到「教学实验」按钮。

**根因**：`experiment.js` 中创建入口按钮的唯一代码 `_buildDom()` 只在 `show()` 内被调用，而 `show()` 只由按钮的 click 事件触发——按钮永远不被创建，形成死锁。`setCatalog()` 只更新卡片内容，不建按钮。

**修复**（已完成，2026-08-25）：
- `experiment.js` 新增公开方法 `init()`；
- `app.js` 初始化时立即调用 `this.experiments.init()`，页面加载即渲染入口按钮；
- 目录未到达时点开显示「等待仿真核心上线…」占位；
- 按钮样式改为品牌蓝高亮（教育主入口应醒目）；
- 脚本缓存版本号升至 `v=3k7`。

验证方式：启动栈后刷新页面，右上角应出现「🧪 教学实验」蓝色按钮。

## 二、对标调研：国家级虚拟仿真教学平台需要什么功能

### 2.1 标杆平台：「实验空间」ilab-x（国家虚拟仿真实验教学课程共享平台）

ilab-x 是教育部主管的国家级共享平台，其功能结构是行业事实标准 [$TRAE_REF](https://www.ilab-x.com/index4)：

| 模块 | 内容 |
|---|---|
| 课程工具 | 虚拟仿真实验课（接口对接、数据采集留存）+ 线上实验课（MOOC 融合） |
| 教学管理 | 教师认证、建立班级、选择实验、导入班级、导出成绩 [$TRAE_REF](https://www.ilab-x.com/topic/2020) |
| 课程建设 | 章节/资源维护、理论学习资源、智能实验室 [$TRAE_REF](https://www.ilab-x.com/course/build/help) |

### 2.2 教学闭环：五环节标配

综合国家级课程的建设规范与各校实践，虚拟仿真实验的教学环节闭环为：

```
课前预习 → 实验操作 → 结果存档 → 报告提交 → 考核评价
```

- **预习**：实验目的/原理/指导资源在线可读，配预习测验；
- **操作**：分步引导 + 步骤赋分模型（每步有目标、用时、赋分）[$TRAE_REF](https://www.ilab-x.com/details/page?id=11977)；
- **存档**：2020 版建设规范明确要求"允许学生保存实验结果（存档），下次登录可恢复" [$TRAE_REF](https://yxxf.swu.edu.cn/uploads/files/da06c47a7b40286f4ed11516ecb2501e.pdf)；
- **报告**：系统生成 + 学生分析 + 在线提交（含得分项细节、总成绩、评语）[$TRAE_REF](https://yxxf.swu.edu.cn/uploads/files/da06c47a7b40286f4ed11516ecb2501e.pdf)；
- **评价**：平台自动评分 + 教师主观评分双轨 [$TRAE_REF](https://www.ilab-x.com/details/page?id=3100)；典型考核权重：签到/预习/操作/报告/理论考核分层计分 [$TRAE_REF](https://www.sy.uestc.edu.cn/cn/article/pdf/preview/10.12179/1672-4550.20220106.pdf)；教师可查看学习记录（提交次数、时间、成绩）并批改 [$TRAE_REF](http://xnfz.hfut.edu.cn/vlab_files/2022/264/0807/m52a.pdf)。

### 2.3 实验界面布局的行业模式

成熟实验系统的界面普遍采用**左侧实验列表 + 中间主工作区 + 右侧/底部结果区**的多面板结构，工作区内再分"实验/数据/操作"选项卡 [$TRAE_REF](https://www.yonghongtech.com/real-help/Z-Suite/10.1/ch/depthanalysis_introductiontotheexperimentinterface.html)；教学型系统则把**参数设置区、功能操作区、原始数据显示区、结果数据显示区**作为四个显式分区 [$TRAE_REF](https://wenku.csdn.net/answer/5jppb8f5r5)。

## 三、差距分析：星桥现状 vs 教学平台标准

| 能力 | ilab-x 等标准 | 星桥现状 | 差距等级 |
|---|---|---|---|
| 实验入口 | 显眼主导航 | 按钮（曾因 bug 不显示，**已修**） | ✅ 已解决 |
| 预习环节 | 指导资源在线 + 测验 | Markdown 指导书在 docs/，**未进界面** | 中 |
| 实验操作 | 参数可调、分步引导 | **参数硬编码只读**，仅"一键运行" | **高（核心差距）** |
| 输入接口 | 显式参数表单 | 无（参数折叠展示，不可改） | **高** |
| 输出接口 | 对账表/图表/得分 | 对账表 + 结论 + HTML 报告下载 | 低（缺图表、缺在线提交） |
| 结果存档 | 服务端存档、可恢复 | 仅浏览器内存，刷新即失 | 高 |
| 报告提交 | 在线提交、教师批改 | 本地下载 | 高 |
| 考核评价 | 自动评分 + 教师评分 | 自动判定（all_pass）无成绩体系 | 高 |
| 班级管理 | 班级/开课/成绩册 | 无 | 高（教师端，可后置） |
| UI 形态 | 教学工位（多面板） | 演示大屏（全屏地球+浮动面板+弹窗） | 中 |

**结论**：星桥目前是"演示系统 + 实验彩蛋"，要成为"教学平台"，核心短板依次是：**① 参数不可调（无输入接口）② 无预习/报告/成绩闭环 ③ UI 形态是展示型而非工位型**。

## 四、UI 重设计方案：双模式拆分

**不建议推翻现有 index.html**——它是竞赛演示的主力（全屏 3D 地球的视觉冲击力是评审加分项）。建议拆成两个模式：

### 4.1 演示模式（index.html，保留现状）

- 全屏 Cesium + 浮动面板，面向答辩/展示；
- 「教学实验」按钮保留（已修复），点击后**跳转**教学模式。

### 4.2 教学模式（新增 lab.html，独立实验台）

```
┌────────────────────────────────────────────────────────────┐
│ 星桥实验台   [实验列表|指导书|我的报告]      学生:____ [返回演示] │ ← 顶部导航
├──────────┬─────────────────────────────────────────────────┤
│ 实验列表  │  ① 实验信息区（目的/原理/理论公式，可折叠）            │
│ ──────── │  ┌─────────────────────┬───────────────────────┐ │
│ ● E1 时延 │  │ ② 输入区（参数表单）    │ ④ 输出区               │ │
│ ○ E2 排队 │  │  ρ 利用率    [0.80] ▁▂▃  │  ┌ 理论-实测对账表 ┐    │ │
│ ○ E3 切换 │  │  λ 到达率    [133.3] pps│  │ 判据|理论|实测|✓  │    │ │
│ ○ E4 QoS │  │  测量窗口    [120] s    │  └────────────────┘    │ │
│          │  │  理论预览: Wq=12.0 ms   │  时序图(canvas)         │ │
│ 完成度    │  │  [▶ 运行] [取消] [重置]  │  结论 + 得分            │ │
│ ▓▓▓░ 1/4 │  │  ③ 进度条/阶段          │  [生成报告][提交]        │ │
│          │  └─────────────────────┴───────────────────────┘ │
│          │  ⑤ 拓扑小图（SVG 节点-链路，随实验场景切换）             │
└──────────┴─────────────────────────────────────────────────┘
```

设计要点：
1. **左栏**：实验列表 + 完成状态（对齐 ilab-x"实验列表"模式 [$TRAE_REF](https://www.yonghongtech.com/real-help/Z-Suite/10.1/ch/depthanalysis_introductiontotheexperimentinterface.html)）；
2. **输入区**：可调参数表单（滑杆/数字框，带范围与单位），理论值随参数**实时联动**（如 ρ 改变时 Wq 立即重算）——这是"输入接口明显"的落地形式；
3. **输出区**：对账表 + 时序图 + 结论 + 得分，与输入区左右并置，一眼看清因果；
4. **拓扑小图**：E1–E4 都是小场景（3–4 节点），用 SVG 画拓扑比 Cesium 地球更贴合教学（包在节点间流动、切换瞬间链路变红），不与主仿真抢 3D 资源；
5. 报告生成沿用现有 HTML 导出，P1 加在线提交。

### 4.3 为什么不直接在 index.html 上改

- 弹窗宽度有限，塞不下"输入表单 + 输出图表"双栏；
- 教学页不需要 60 FPS 的 1584 星渲染，独立页面性能压力小、可在低配机房电脑运行；
- 双模式保留演示冲击力（竞赛）与教学可用性（课程）两个场景，互不妥协。

## 五、输入/输出接口设计（Schema 驱动）

这是本次调研最重要的技术结论：**用声明式 Schema 定义每个实验的输入与输出，前端自动生成表单与结果区**，接口因此"天生明显"。

### 5.1 输入 Schema（核心侧 experiments.py 扩展）

```python
"E2": {
    "inputs": [
        {"key": "rho",  "label": "利用率 ρ", "type": "float",
         "min": 0.3, "max": 0.95, "step": 0.05, "default": 0.8,
         "unit": "", "tip": "ρ→1 时排队时延呈悬崖式增长"},
        {"key": "window_s", "label": "测量窗口", "type": "int",
         "min": 30, "max": 300, "step": 30, "default": 120, "unit": "s"},
    ],
    "theory": lambda p: {"Wq_ms": p["rho"] * 6 / (2 * (1 - p["rho"])) * 1000},
}
```

- `experiment_run` 命令扩展 `params` 字段：`{"exp_id": "E2", "params": {"rho": 0.9}}`；
- 核心侧 runner 改为接收参数（目前 E2 的 ρ/窗口、E3 的队列容量、E4 的两流速率都是现成变量，改造成本低）；
- **理论值随参数动态计算**，对账容差按参数区间设定（ρ>0.9 时统计涨落大，容差放宽）；
- 固定种子仍保留为默认，"探索模式"参数可变 + "考核模式"参数锁定，正好对应 ilab-x 的练习/考核双模式 [$TRAE_REF](https://www.ilab-x.com/details/page?id=11293&isView=true)。

### 5.2 输出 Schema

每个实验声明输出组件，前端按声明渲染：

```python
"outputs": [
    {"type": "verdict_table"},                    # 理论-实测对账表（已有）
    {"type": "timeseries", "metric": "e2e_ms"},   # 时序图（复用 chart.js）
    {"type": "topology_svg"},                     # 拓扑动画
    {"type": "score", "weights": {...}},          # 得分（P2）
]
```

### 5.3 接口显式化的三条原则

1. **输入在左、输出在右，永远同屏**——学生调参数能立刻看到理论预览变化，跑完看到实测对照；
2. **每个输入有单位、范围、提示**——表单自动校验（min/max）；
3. **输出必含"理论 vs 实测"**——这是星桥区别于普通动画仿真平台的核心卖点，必须视觉上最强。
