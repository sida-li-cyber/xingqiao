## 1. 实验目的

- 理解 Kendall 记号 M/D/1 的含义：泊松到达、确定性服务、单服务台；
- 掌握 M/D/1 平均排队时延公式并验证它与仿真的吻合度；
- 学会"预热 + 稳态测量窗"的仿真实验方法学。

## 2. 预备知识

M/D/1 在利用率 ρ < 1 时的平均排队（等待）时延为 Pollaczek–Khinchine
公式的特例：

```
Wq = ρ·s / (2·(1 − ρ))        s 为服务时间，ρ = λ·s
```

本实验的瓶颈配置：

| 参数 | 值 |
|------|-----|
| 瓶颈链路 | R1 → GS（GSL） |
| 瓶颈容量 C | 2 Mbps |
| 包长 | 1500 B → 服务时间 s = 12000 bit / 2 Mbps = **6 ms** |
| 到达率 λ | 133.33 pps（泊松） |
| 利用率 ρ | λ·s = **0.8** |
| 理论 Wq | 0.8 × 6 / (2 × 0.2) = **12 ms** |

端到端时延预测（传播 6 ms + ISL 发送 ≈ 0 + 服务 6 ms + 排队 12 ms）：

```
e2e ≈ 24 ms
```

**方法学要点**：排队系统需要从空系统演化到稳态。本实验先空跑 60 s
预热（丢弃统计），再用 120 s 测量窗取均值——这正是真实网络测量中
"warm-up + measurement window"的标准做法。

## 3. 实验步骤

1. 启动平台，打开 **「教学实验」** 面板；
2. 展开 E2 卡片的"实验参数"，核对上表；
3. 点击 **「运行实验」**，观察两个阶段：
   - `预热`（0%）：队列从空系统向稳态演化；
   - `数据测量`（0 → 100%）：12 段 × 10 s 测量窗；
4. 结束后核对三行判据，记录实测 e2e 与利用率。

## 5. 思考题

1. 把 ρ 从 0.8 提高到 0.95，Wq 变为多少？（37 → 57 ms；解释 1/(1−ρ)
   的"悬崖效应"对网络容量规划的启示）
2. 为什么本实验要把预热期的数据丢弃？若从 t=0 直接统计，测得的
   e2e 会偏大还是偏小？
3. M/M/1 的 Wq 是 M/D/1 的两倍（ρs/(1−ρ) vs ρs/2(1−ρ)）——直观
   解释"服务时间的随机性"如何加剧排队。

## 6. 延伸

真实卫星网络汇聚流量更接近泊松叠加。可对照 E4：当两类业务共享
瓶颈时，尽力流承担的排队代价正是本实验 Wq 的"拥塞放大版"。
