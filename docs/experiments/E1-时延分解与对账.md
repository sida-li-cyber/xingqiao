# E1 时延分解与对账

| | |
|---|---|
| 实验编号 | E1 |
| 建议课时 | 45 min |
| 难度 | 入门 |
| 前置知识 | 网络时延四分量（发送、传播、排队、处理） |
| 对应代码 | `satviz/experiments.py::_run_e1`，判据源自 `tests/test_packet_sim.py` Test 1 |

## 1. 实验目的

- 掌握端到端时延的两个物理分量：**发送时延**与**传播时延**；
- 理解"轻载链路上排队时延趋近于零"这一工程近似；
- 学会用理论公式预测仿真结果，并解释误差来源。

## 2. 预备知识

数据包从 A 到 B 的端到端时延在轻载条件下近似为：

```
e2e ≈ Σ(传播时延) + Σ(发送时延)
```

**传播时延**只取决于链路物理长度：t_prop = L / c（真空光速）。
**发送时延**取决于包长与链路容量：t_ser = packet_bits / capacity_bps。

本实验的三跳链路（UAV-1 → Sat-A → Sat-B → GS-1）：

| 链路 | 类型 | 容量 | 传播时延 | 发送时延 (1500 B) |
|------|------|------|----------|-------------------|
| UAV-1 → Sat-A | SUL | 500 Mbps | 5 ms | 0.024 ms |
| Sat-A → Sat-B | ISL | 10 Gbps | 10 ms | 0.0012 ms |
| Sat-B → GS-1 | GSL | 1 Gbps | 6 ms | 0.012 ms |

理论预测：

```
e2e ≈ (5 + 10 + 6) ms + 0.037 ms ≈ 21.037 ms
```

业务源只有 10 pps（轻载），队列几乎恒空，因此排队分量可忽略。

## 3. 实验步骤

1. 双击 `start_starbridge.bat` 启动平台；
2. 点击右上角 **「教学实验」**，打开 E1 卡片，展开"实验参数"核对上表；
3. 点击 **「运行实验」**，观察 30 s 仿真推进（进度条 ~15 s 实际时间）；
4. 查看对账表，回答：**三个分量中谁贡献最大？谁几乎可以忽略？**

## 5. 思考题

1. 若把业务源从 10 pps 提高到 10,000 pps，哪个分量会先失效？为什么？
2. 星间链路（ISL）传播 10 ms 对应约 3000 km 星间距离——查证 Starlink
   同轨道面相邻卫星间距是否与此同数量级；
3. 发送时延 0.037 ms 为什么远小于传播时延 21 ms？这对卫星网络
   "带宽丰富、时延昂贵"的特点意味着什么？

## 6. 延伸

把本实验与 E2 对照：E1 是"排队项 ≈ 0"的特例，E2 则专门测量排队项。
两实验合起来即完整的时延分解教学闭环。
