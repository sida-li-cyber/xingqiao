# E3 链路切换丢包

| | |
|---|---|
| 实验编号 | E3 |
| 建议课时 | 45 min |
| 难度 | 进阶 |
| 前置知识 | 队列容量、在途包（in-flight）、LEO 星地切换 |
| 对应代码 | `satviz/experiments.py::_run_e3`，判据源自 `tests/test_phase3.py` Test 3 |

## 1. 实验目的

- 理解 LEO 卫星高速运动导致的**链路切换**及其丢包机理；
- 掌握切换瞬间丢包尖峰的定量推导：**队列容量 + 在途 1 包**；
- 区分"切换丢包"（handover）与"拥塞丢包"两种统计口径。

## 2. 预备知识

低轨卫星相对地面高速运动（~7.6 km/s），地面终端与卫星的可见窗口
只有几分钟，网络必须周期性切换接入卫星。切换瞬间：

1. 旧链路上**已入队**的包：队列被拆除，全部丢失；
2. 旧链路上**在途**（已发送未到达）的包：链路断开，丢失；
3. 新链路建立后路由重算，后续包走新路径恢复。

若切换前上行链路已被超速业务堆积到满队列（容量 Q 包），则切换
瞬间的一次性丢包尖峰为：

```
尖峰 = Q（在队） + 1（在途） = 200 + 1 = 201 包
```

本实验以 3000 pps 注入 1 Mbps 上行（超额 ~37 倍），10 s 内把
200 包的队列堆满，随后撤销 Sat-A 链路、改走 Sat-B，观察尖峰。

## 3. 实验步骤

1. 启动平台，打开 **「教学实验」** 面板；
2. 展开 E3 卡片"实验参数"核对：队列容量 200 包、切换时刻 10 s；
3. 点击 **「运行实验」**，观察三个阶段：
   - `队列堆积`（0 → 10 s）：超速业务填满上行队列；
   - 切换瞬间（瞬时完成）：Sat-A → Sat-B；
   - 恢复期（10 → 20 s）：新路径恢复送达；
4. 核对对账表三行判据，重点关注"是否全部计入 handover 口径"。

## 4. 判据与记录

| 判据 | 理论值 | 容差 |
|------|--------|------|
| 切换丢包尖峰 | 201 包 | ±1 包 |
| 全部计入 handover 口径 | = 尖峰数 | 0 |
| 切换后 10 s 送达 | > 0（恢复） | — |

示例实测（固定种子 7）：尖峰 201 包，口径一致，恢复期送达正常。
导出报告并提交。

## 5. 思考题

1. 把队列容量从 200 降到 50，切换尖峰变为多少？这说明"加大缓存"
   对切换丢包是治本还是治标？
2. 若终端同时可见 2 颗卫星并采用 make-before-break（先建后断）切换，
   尖峰会怎样变化？平台中对应哪种工程策略？
3. E3 的丢包是"瞬时尖峰"，E2 的稳态丢包为 0——一次传输应优先
   避开哪种场景？这对低轨网络的调度算法意味着什么？

## 6. 延伸

主界面可观察真实星座的 GSL 链路随时间批量建立/断开——那正是
E3 场景在 1584 星规模上的连续上演。切换丢包口径的精确统计
（handover vs congestion）是平台包级引擎的核心能力之一。
