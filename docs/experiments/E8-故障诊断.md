# E8 链路故障诊断

| | |
|---|---|
| 实验编号 | E8 |
| 建议课时 | 45 min |
| 难度 | 进阶 |
| 前置知识 | 拥塞与丢包机理（E4/E5）、分段排查（bisect）思想 |
| 对应代码 | `satviz/experiments.py::_run_e8`，判据源自 `tests/test_experiments.py` E8 用例 |

## 1. 实验目的

- 掌握**观测 → 边界 → 假设 → 提交证据**的故障定位方法学；
- 理解"容量骤降型隐蔽故障"的拥塞特征：只有故障链路拥塞，
  其余链路畅通；
- 学会用低速率监视流做**无扰观测**，凭丢包率与时延的干净/劣化
  分界推断根因链路，并撰写可复核的证据链。

## 2. 预备知识

### 2.1 容量骤降拥塞模型

雨衰等原因可使一条链路的有效容量骤降。设链路正常容量 C，
故障后有效容量 C' = α·C（本实验 α = 0.15）。业务速率 λ 满足：

```
C' < λ < C        （其余链路畅通、故障链路拥塞）
```

此时**只有**故障链路持续排队溢出：穿过故障段的流丢包率高、
时延陡增；不穿过故障段的流完全正常。这正是"隐蔽故障可被
分段观测捕获"的物理基础。

### 2.2 观测边界定位法（bisect）

线性链 GS-A—S1—S2—S3—S4—GS-B（链路 L1~L5），其中一条内部
链路（L2/L3/L4 之一）容量被压至 15%，具体位置由运行种子决定。

观测手段：向某个中间节点布设**低速率监视流**（速率 ≈ 主业务的
5%，不改变拥塞状态），该流从 GS-A 出发、与主业务同路经：

- 监视流目的节点在故障段**上游** → 路径未穿过故障链路，
  丢包 ≈ 0、时延正常（**干净**）；
- 目的节点在故障段**下游** → 路径穿过故障链路，丢包率高、
  时延陡增（**劣化**，平台按丢包率 ≥ 20% 判定）。

相邻"干净/劣化"两节点的分界所在链路即根因。本实验配置：

| 参数 | 值 |
|------|-----|
| 拓扑 | 线性链 6 节点，链路 L1~L5 |
| 链路容量 C | 2 Mbps（≈ 167 pps @1500 B） |
| 故障链路容量 | C × 0.15 ≈ 25 pps |
| 主业务 λ | GS-A → GS-B，100 pps |
| 探测监视流 | 每节点 5 pps（探测预算 ≤ 3 个节点） |
| 预热 / 测量 | 15 s / 30 s |

## 3. 实验步骤（两阶段）

**第一阶段 · 观测**

1. 启动平台，打开实验台选择 E8；
2. 在「探测节点」填 1~3 个节点（逗号分隔，如 `S2,S4`），
   **先不填**根因链路与证据链；
3. 点击「运行实验」，读取**探测观测表**：各节点的丢包率 /
   e2e 时延 / 发送 / 丢弃，以及"正常 / 劣化"标记；
4. 定位边界：找出丢包 ≈ 0 与丢包高的相邻节点分界
   （若全部干净，说明故障在探测覆盖之外，应调整探测组合
   扩大覆盖后重跑）。

**第二阶段 · 提交**

5. 在「根因链路」填入推断结论（L1~L5 之一）；
6. 在「证据链」引用观测数据说明上游/下游对比
   （如"XX 节点干净、YY 节点劣化，故障在两者之间的链路段"）；
7. 再次运行，核对对账表；未命中时按结论区引导语收紧探测边界重试；
8. 填写「分析结论」，下载报告并回答思考题。

## 4. 判据与记录（诊断型，判据带权重）

| 判据 | 权重 | 判定 |
|------|------|------|
| 根因链路定位 | 70% | 提交的链路与注入故障一致 |
| 证据链完整性 | 30% | 引用上游/下游对比或探测节点数据 |
| 探测预算（≤ 3 个节点） | 0%（只约束不计分） | 超预算不扣分但计入对账行 |

本实验不设参数扫描分（评分卡注明"诊断型实验以判定计分"），
总分由定位 + 证据链 + 预习测验 + 思考题构成。每次运行的参数与
结果自动记入「参数-结果历史」，可对照多次探测组合的观测差异。

## 5. 思考题

1. 监视流速率为什么必须远小于主业务速率？若把探测流量放大
   20 倍，观测结论可能被怎样污染？
2. 若所有探测节点全部"干净"（丢包 ≈ 0），能得出什么结论？
   下一步应把探测节点移到哪里？
3. 现实网络运维中，除丢包率与时延外，还有哪些可作分段排查的
   观测量？它们各自对应什么类型的故障？

## 6. 延伸

E5（路由对比）说明"拥塞如何被绕开"，本实验说明"拥塞如何被
定位"；两者合起来即网络故障诊断的"发现—定位—处置"闭环。
若时间充裕，可结合 E7（雨衰）讨论容量骤降型故障的物理成因。
